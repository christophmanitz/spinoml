## System context

Two orthogonal axes (see CLAUDE.md):

- **Execution mode** — `browser` (Vite dev, localStorage virtual FS) vs
  `tauri` (Rust shell, real FS, auto-spawned sidecars, SSH, terminal). Decided by
  `workspace/store.ts.mode`, sniffed via `isTauri()`.
- **FS backend** (Tauri mode only) — `local` (Tauri `fs::*`) vs `remote-ssh`
  (system `ssh`). The switch lives **only** in `src/connections/backend.ts`;
  every consumer dispatches through it.

Additionally the app has **one model canvas (architecture) and two satellite
canvases** — training graph and data graph — each file-bound
(`src/canvasdoc/`), generated by their own generators, and driveable by the
chatbot.

## Component inventory

### 1. Frontend app shell

- Files: `src/main.tsx`, `src/App.tsx`, `src/Toolbar.tsx`, `src/ErrorBoundary.tsx`,
  `src-tauri/tauri.conf.json`, `src-tauri/capabilities/default.json`.
- Inputs: user gestures; boot-time restore of active file/autosave; layout
  persists via `react-resizable-panels` (localStorage keys `spinoml.{cols,center,right,left}.v1`).
- Outputs: 3-column resizable layout (Palette+Sidebar | Canvas+BottomTabs | Inspector+Chat);
  header badges (inference, LLM, remote sidecar, Explain).
- State: layout (localStorage), UI stores (`sidebarStore`, `uiStore`).
- External deps: react 19, @xyflow/react 12, react-resizable-panels 4, monaco,
  xterm, tailwind 4, vite 8.
- Failure modes: render crash → ErrorBoundary (survives); `flex-1` inside Panel
  breaks (use `h-full w-full`); Rust-spawned sidecar die-on-first-request.
- Tests: none; `npm run build` (tsc) is the gate.

### 2. GraphStore (in-memory graph — THE source of truth)

- Files: `src/canvas/GraphStore.ts` (zustand), `src/canvas/subgraphPorts.ts`,
  `src/canvas/scopeStore.ts`, `src/canvas/layout.ts`+`layoutStore.ts`,
  `src/history/store.ts`.
- Inputs: React Flow `onNodesChange`/`onEdgesChange`/`onConnect`; LLM tools →
  `addLayer`/`updateNodeParams`/`connectNodes`/`deleteNode`; `loadSnapshot`/`resetGraph`;
  `autoLayout`.
- Outputs: `nodes` (layerType, params, inferred I/O shapes, hasError), `edges`,
  `selectedNodeId`; snapshot helpers (`captureSnapshot` incl. positions for
  persistence/history; `captureStructuralSnapshot` for dirty/history triggers).
- State: `{ nodes, edges, selectedNodeId }` — single list, no parallel node maps.
- External deps: zustand, @xyflow/react, `layers/registry` (coerceParams).
- Invariants: `coerceParams` on **every** params write; structural-only undo
  history (50 deep, positions intentionally not undoable); `activeFileId` always
  exists; subgraph auto-port sync via `reconcileSubgraphPorts`.
- Failure modes: coercion miss → renderer throw → ErrorBoundary (documented);
  shape-inference feedback loops (guarded in inference store); proxy-reconcile
  is O(n·subgraph) JSON compare per edge op.
- Tests: **none** (store imperative logic not exercised by any harness).

### 3. Layer registry

- Files: `src/layers/registry.ts` (LAYERS spec list), `src/layers/*`.
- Inputs: layer `type`, category, `pytorchModule`, FieldSpecs, default params.
- Outputs: `defaultParamsFor` + `coerceParams` (LLM-supplied values sanitised
  here — mandatory for any new FieldSpec kind).
- State: static registry.
- Failure modes: missing FieldSpec renderer/coercion → crash/HQW; new layers
  that break sequential codegen need `generator.ts` awareness.
- Tests: `verify-codegen.ts` exercises generation for the registered layers (13
  graphs); no per-layer unit tests.

### 4. Code generation (graph → PyTorch)

- Files: `src/codegen/generator.ts` (model), `src/training/trainingGenerator.ts`
  (training graph → trainer source), `src/codegen/CodePreview.tsx` (Monaco).
- Inputs: `captureStructuralSnapshot`-shaped node/edge arrays; training graph
  nodes (DatasetSource/Split/DataLoader/ModelSource/Loss/Optimizer/TrainLoop/
  Head); project deps.
- Outputs: deterministically emitted `nn.Module` Python (+ `train.py` for runs),
  `.py` twin (`pyTwinPath` in workspace/store.ts:67).
- State: **pure** — no I/O, randomness, or `Date.now()` (invariant; verify harness
  depends on it).
- Details: Graph input → `Data` forward-arg; GNN/pool consumers get explicit
  `x, edge_index, batch = g.x, …`, Custom/Subgraph consumers get whole Data;
  DataOp is a pure passthrough (aliases predecessor var).
- Failure modes: multi-input/branching layers must be taught in generator;
  serialization of exotic FieldSpecs.
- Tests: `verify-codegen.ts` — 13/13 PASS at baseline; `verify-traingen.ts` —
  compile + multitask + external-validation e2e PASS.

### 5. Shape inference

- Files: `src/inference/client.ts` (HTTP→torch sidecar), `src/inference/store.ts`
  (debounced subscriber); sidecar `/infer`.
- Inputs: `inferredInputShape` writebacks; full model code + Data sample.
- Outputs: `inferredOutputShape` per node; `failingNodeId` for fix hints.
- State: ephemeral per-node shapes written into GraphStore; **never** in a
  parallel store.
- External deps: torch sidecar (127.0.0.1:7421), Python + torch.
- Failure modes: feedback loop (guarded by identity-check + `applyingShapes`);
  sidecar offline → shape (auto) unavailable but non-fatal; graph input handling
  (whole Data objects); synthetic edge_index random graphs for GNN viz.
- Tests: `verify-sidecar.ts` covers /infer happy + intentional error.

### 9. Torch sidecar

- Files: `sidecar-torch/main.py` (HTTP/JSON 127.0.0.1:7421), `dataset_handlers.py`,
  `training_template.py`, `sidecar-torch/espf/` (vendored MolTrans BPE codebook).
- Endpoints: `/infer`, `/dataset/inspect|stats|smoke`, `/activations`, `/run_script`.
- Inputs/Outputs: model code + sample tensors → shapes/activations; dataset
  abspaths → inspect/stats/smoke.
- State: none persistent (caches live beside datasets under `.graphcache/.espf`);
  port overridable via env (Phase 12b remote deploy).
- External deps: torch (+ heavy optional deps lazy-imported), python ≥3.9; remote

- Failure modes (AUDIT §1): CORS `*` no auth (CSRF — code exec from any browser),

  pickle RCE for foreign `.pt`. Counted as release blockers in plan §77/78.
- Tests: `verify-sidecar.ts` (autostart + happy/error) 6/6 + activations PASS.

### 10. LLM sidecar

- Files: `sidecar-llm/main.mjs` (HTTP/SSE 127.0.0.1:7422), `mcp-bridge.mjs`.
- Providers (payload `llm.kind`): **opencode** (default; spawns
  `opencode run --format json -m <model>` per turn, tools exposed ONLY via MCP
  bridge), `subscription` (claude-agent-sdk + OAuth, in-process MCP), `anthropic`,
  `openai-compat` (OpenAI/Gemini/Ollama via openai SDK).
- Tool registry: `buildToolSpecs()` — provider-neutral; graph mutation tools,
  read/write/list, `run_script` (mode `shell` = login-node w/ ~2-min cap;
  mode `slurm` = sbatch), `slurm_status`, notes/dataset tools, `ask_user`.
- Ask/confirm channel: `askUser()` → SSE `ask`, `POST /respond` answers it
  (pendingAsks per-turn registry); run_script is GUI-gated.
- State: in-memory `ctx` mutated per turn; per-turn MCP session registry (bridge);
  pendingAsks.
- Failure modes (AUDIT §1): CORS `*` + auto-approve path no auth; `/respond`
  endpoint unauthenticated. Chat stream errors surface as status events.
- Tests: `verify-opencode.ts` (models list, real chat, bogus-model error) PASS.

### 11. MCP

- Files: `sidecar-llm/mcp-bridge.mjs` (stdio ↔ `POST /internal/mcp/<requestId>/list|call`);
  subscription path has an in-process equivalent.
- Inputs: LLM tool calls. Outputs: tool specs (buildToolSpecs shadow) + results;
  same handlers, same SSE `actions` mirror.
- Purpose: ALL provider tools flow through the same validation gate as Claude
  (single registry = single truth for what the model may do).
- Failure modes: tool spec drift between providers; permission/allow-list mismatch
  (`allowedTools` subscription-only).
- Tests: none dedicated.

### 12. Tauri shell

- Files: `src-tauri/src/lib.rs`, `tauri.conf.json`, `capabilities/default.json`.
- Responsibilities: window, workspace-Scoped FS commands (`WorkspaceState.resolve`

- Failure modes: a Rust command not in `generate_handler!` is silently unreachable;

- Tests: none in-repo (Rust toolchain absent on dev machine → cargo check SKIPPED

### 13. Rust commands

- Files: `src-tauri/src/lib.rs`, `src-tauri/src/ssh.rs`, `src-tauri/src/training.rs`,
  `src-tauri/src/pty.rs`.
- Command surface: local `fs::*`; `ssh_*` mirrors (BatchMode ssh subprocesses);
  PTY sessions; training run launch/stop/status for local+remote.
- Security patterns: `resolve(&root,&relpath)` (reject `..`/absolute);
  `shell_quote_path`/`shell_quote` for every user string into shell;
  validate_alias/validate_remote_root/validate_relpath.
- Failure modes: forgetting the ssh mirror breaks remote silently; quoting bugs →
  command injection (risk covered in plan §44).
- Tests: none.

### 14. Filesystem (local + remote)

- Files: `src/workspace/tauri-fs.ts`, `src/connections/tauri-ssh.ts`,
  `src/connections/backend.ts`.
- `backend.ts` is the ONLY dispatch layer (`fs/project/notes/experiments/datasets`);
  consumers must never import tauri-fs/tauri-ssh directly (invariant).
- Local: real FS under workspace root via Tauri. Remote: system ssh (BatchMode,
  agent/GSSAPI; no secrets stored).
- Failure modes: ssh exit 255 (password prompts auto-fail — user must use keys);

- Tests: none; manual (`ssh <alias> echo ok` then UI).

### 18. SLURM (remote high-throughput path)

- Tests: none automated (remote GPU untested from this laptop).

## Remote ↔ local dispatch summary

```
consumer (workspace/project/datasets/training...) 
      │ getCurrentConnection()          -- src/connections/store.ts
      ▼
src/connections/backend.ts  ── local  → tauri-fs (Tauri fs::*)
                             └ remote → tauri-ssh (Rust ssh_* over BatchMode ssh)
```

Sidecar URLs: local run always on 127.0.0.1 (torch 7421, llm 7422); remote
workspace tunnels the torch-sidecar port (7424) for Phase 12a; full HPC-side
sidecar = Phase 12b (`<root>/.spinoml/venv` already provisioned on the cluster).
