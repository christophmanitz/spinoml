## System context

Two orthogonal axes (see CLAUDE.md):

- **Execution mode** — `browser` (Vite dev, localStorage virtual FS) vs
  `tauri` (Rust shell, real FS, auto-spawned sidecars, SSH, terminal). Decided by
  `workspace/store.ts.mode`, sniffed via `isTauri()`.
- **FS backend** (Tauri mode only) — `local` (Tauri `fs::*`) vs `remote-ssh`
  (system `ssh`). The switch lives **only** in `src/connections/backend.ts`;
  every consumer dispatches through it.

Additionally the app has **one model canvas (architecture) and two satellite
canvases** — training graph and data graph — each file-bound
(`src/canvasdoc/`), generated by their own generators, and driveable by the
chatbot.

- External deps: react 19, @xyflow/react 12, react-resizable-panels 4, monaco,

  breaks (use `h-full w-full`); Rust-spawned sidecar die-on-first-request.
- Tests: none; `npm run build` (tsc) is the gate.

### 2. GraphStore (in-memory graph — THE source of truth)

- Files: `src/canvas/GraphStore.ts` (zustand), `src/canvas/subgraphPorts.ts`,
  `src/canvas/scopeStore.ts`, `src/canvas/layout.ts`+`layoutStore.ts`,
  `src/history/store.ts`.
- Inputs: React Flow `onNodesChange`/`onEdgesChange`/`onConnect`; LLM tools →
  `addLayer`/`updateNodeParams`/`connectNodes`/`deleteNode`; `loadSnapshot`/`resetGraph`;
  `autoLayout`.
- Outputs: `nodes` (layerType, params, inferred I/O shapes, hasError), `edges`,
  `selectedNodeId`; snapshot helpers (`captureSnapshot` incl. positions for
  persistence/history; `captureStructuralSnapshot` for dirty/history triggers).
- State: `{ nodes, edges, selectedNodeId }` — single list, no parallel node maps.
- External deps: zustand, @xyflow/react, `layers/registry` (coerceParams).
- Invariants: `coerceParams` on **every** params write; structural-only undo
  history (50 deep, positions intentionally not undoable); `activeFileId` always
  exists; subgraph auto-port sync via `reconcileSubgraphPorts`.
- Failure modes: coercion miss → renderer throw → ErrorBoundary (documented);
  shape-inference feedback loops (guarded in inference store); proxy-reconcile
  is O(n·subgraph) JSON compare per edge op.
- Tests: **none** (store imperative logic not exercised by any harness).

### 3. Layer registry

- Files: `src/layers/registry.ts` (LAYERS spec list), `src/layers/*`.
- Inputs: layer `type`, category, `pytorchModule`, FieldSpecs, default params.
- Outputs: `defaultParamsFor` + `coerceParams` (LLM-supplied values sanitised
  here — mandatory for any new FieldSpec kind).
- State: static registry.
- Failure modes: missing FieldSpec renderer/coercion → crash/HQW; new layers
  that break sequential codegen need `generator.ts` awareness.
- Tests: `verify-codegen.ts` exercises generation for the registered layers (13
  graphs); no per-layer unit tests.

### 4. Code generation (graph → PyTorch)

- Files: `src/codegen/generator.ts` (model), `src/training/trainingGenerator.ts`
  (training graph → trainer source), `src/codegen/CodePreview.tsx` (Monaco).
- Inputs: `captureStructuralSnapshot`-shaped node/edge arrays; training graph
  nodes (DatasetSource/Split/DataLoader/ModelSource/Loss/Optimizer/TrainLoop/
  Head); project deps.
- Outputs: deterministically emitted `nn.Module` Python (+ `train.py` for runs),
  `.py` twin (`pyTwinPath` in workspace/store.ts:67).
- State: **pure** — no I/O, randomness, or `Date.now()` (invariant; verify harness

- Details: Graph input → `Data` forward-arg; GNN/pool consumers get explicit
  `x, edge_index, batch = g.x, …`, Custom/Subgraph consumers get whole Data;
  DataOp is a pure passthrough (aliases predecessor var).
- Failure modes: multi-input/branching layers must be taught in generator;
  serialization of exotic FieldSpecs.
- Tests: `verify-codegen.ts` — 13/13 PASS at baseline; `verify-traingen.ts` —
  compile + multitask + external-validation e2e PASS.

## Remote ↔ local dispatch summary

```
consumer (workspace/project/datasets/training...) 
      │ getCurrentConnection()          -- src/connections/store.ts
      ▼
src/connections/backend.ts  ── local  → tauri-fs (Tauri fs::*)
                             └ remote → tauri-ssh (Rust ssh_* over BatchMode ssh)
```

workspace tunnels the torch-sidecar port (7424) for Phase 12a; full HPC-side
sidecar = Phase 12b (`<root>/.spinoml/venv` already provisioned on the cluster).

#### Who spawns whom

  this happens at app start. In browser dev, the sidecars are
  started manually (`npm run sidecar:torch`, `npm run sidecar:llm`).
- **Rust (`spawn_blocking` inside `ensure_remote_sidecar`,
  `remote_sidecar.rs:466-473`)**: spawns one long-lived ssh
  subprocess that holds the `-L 7424:7421` tunnel AND the remote
  python sidecar in the same channel.
- **Rust (`start_training_run`, `src-tauri/src/training.rs:501-563`)**:
  spawns the local trainer via `setsid python -u train.py` inside the
  run dir. Setsid detaches the process group so the trainer outlives
  the app.
- **Rust (`ssh_start_training_run`, `src-tauri/src/ssh.rs:927-1048`)**:
  on the remote, runs `nohup setsid <python> -u train.py` (direct)
  or `sbatch train.sbatch` (SLURM).
- **No parent-child relationship between torch and llm sidecars** —
  they're independent children of the Rust shell.

### C. Data flow of a training run (end to end)

```
graph (Zustand GraphStore)
        │
        │  NewRunModal → src/training/{graph,backend}.ts
        │   - verifies the model is verified for training (verify:verifier)
        │   - freezes the graph + generated model + train.py into run.json
        ▼
run.json (frozen, sha256'd by manifest later)
   ├── training: {epochs, batch_size, seed, optimizer, loss, ...}
   ├── dataset:  {kind, path|relpath, fingerprint: {alg, hash, mode}}
   ├── snapshot: {graph_sha256, model_py_sha256, preprocessing[], code_trust[]}
   ├── resume_from (optional)
   ├── eval_only + validate.checkpoint_from (optional, for external validation)
   └── backend: {kind: "local"|"slurm", slurm: {partition, time, ...}}
        │
        │  Rust: start_training_run (local) OR ssh_start_training_run (remote)
        │   - atomic claim (mkdir or MLF_CREATED markers)
        │   - drop trainer in as train.py (snapshot — train.py is immutable per run)
        │   - write status="queued", launch detached / sbatch
        ▼
Run dir (experiments/runs/<id>/)
   ├── run.json, model.spinoml, model.py, train.py   ← frozen
   ├── status          ← state machine
   ├── events.jsonl    ← append-only, fsync per line
   ├── metrics.json    ← rewritten at terminal states
   ├── manifest.json   ← rewritten on every state change
   ├── checkpoints/{best.pt, last.pt}  ← _atomic_save (tmp + fsync + replace)
   ├── pid             ← "12345" (setsid) or "slurm:12345" (sbatch)
   └── stdout.log, stderr.log (executor) OR train.sbatch + slurm-<jid>.out|err (SLURM)
        │
        │  Python: python -u train.py  (train.py = sidecar-torch/training_template.py, snapshotted)
        │
        │  Inside train.py (sidecar-torch/training_template.py):
        │   - verify run.json hash (snapshot)
        │   - read manifest / verify fingerprint
        │   - emit run.provenance, config.env, run.snapshot, run.determinism
        │   - load dataset (load_tabular / load_manifest_graphs)
        │   - split + collate (Phase 19 zero-overlap check)
        │   - build Model + optimizer (lazy-materialize lazy layers via dummy forward)
        │   - eval-only? load validate.checkpoint_from, evaluate, write metrics, integrity gate, exit
        │   - resume_from? safe_torch_load + restore rng, emit run.resumed
        │   - epoch loop:
        │       require_finite(loss) + require_finite(gradients)
        │       _atomic_save best.pt when val improves
        │       emit epoch.start / batch / epoch.end
        │       cooperative cancel check at each epoch boundary
        │   - _atomic_save last.pt at the end (or after cancel/signal/exception at last completed epoch)
        │   - write metrics.json with status=done (full payload)
        │   - _verify_run_integrity (Phase 73): metrics / checkpoints / events / manifest / logs
        │       fail closed → fail("integrity", ...) → status=failed, run.failed event
        │   - transition_status("done") → emit run.done
        │   - _manifest_write(done) + _record_terminal_resumable (Phase 74)
        │
        │  On signal (SIGTERM/SIGINT):
        │   - _on_cancel → raise _Cancelled → caught at epoch loop boundary
        │   - save last completed epoch's checkpoint (best-effort)
        │   - _finish_cancel → terminal-shielded cancelled, run.cancelled event
        │
        │  On exception:
        │   - try-save last completed epoch's checkpoint (best-effort)
        │   - fail("train", msg, tb) → status=failed, run.failed event
        ▼
UI tail:
   - events.jsonl streamed → epoch.end charts (per-head metric namespaced)
   - manifest.json → git provenance, reproducibility statement, hardware/software
   - metrics.json.resumable → UI banner
   - on done: integrity gate output surfaces in run.integrity event
```

The state machine (queued → running → done|failed|cancelled) is the
single source of truth. Events are immutable history; the `status`
file is the LIVE state; the terminal states are FINAL (no late event
can resurrect a `done` run into `cancelled`). See FAILURE_RECOVERY.md
§1 for the full transition table.
