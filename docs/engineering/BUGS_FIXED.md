# Bugs fixed (final reliability report, TODO §90.4)

This is the honest, source-traceable catalogue of defects that were found and
fixed during the hardening work. Every row names the source it comes from
(`RISK_REGISTER.md`, a commit body, a `TODO.md` implementation note, or one of
the audit documents) and the commit that fixed it.

## Method

**What counts as a bug (a defect).** A behaviour that was wrong in the shipped
code, or that a review, test, fuzz run or manual probe proved reachable: a
false success, a wrong state, a silent empty/invented value, an unguarded crash,
an injection/escape, a data-corruption path, or a green test that encoded a
wrong or missing behaviour. One row per defect, not one row per phase.

**What is not counted as a bug.** Feature work (a new provider, canvas, or
tokenizer that never claimed to work before) and pure verification coverage
with no observed wrong behaviour are *not* defects here, even when a register
row exists for them — they are listed under "Not bugs". Documentation
corrections and false alarms are also separated. The one deliberate exception:
defects in the test apparatus itself are included when the brief names them
(the auth suite driving the real Claude CLI, the runner leaking sidecars, the
leak-detector grace, the CSP suite on Node 20), because a lying test is a real
process defect.

**ID rule.** `R…` is used when a register row is specifically about that defect;
otherwise `H-001`, `H-002`, … in commit order. When one register row bundles
several distinct defects, the first gets the `R`-id and the named extras get
`H`-ids (noted per row). When a register row covers only missing tests it is
skipped and listed under "Not bugs".

**Severity.** The register's severity where the register has the row; otherwise
a reading of the TODO §86 scale (CRITICAL / HIGH / MEDIUM / LOW), marked with
`*`. CRITICAL = scientific correctness, data integrity, security or experiment
validity; HIGH = major operational failure; MEDIUM = clear defect unlikely to
invalidate results silently; LOW = cosmetic/convenience.

**Commit.** The short hash of the fixing commit, copied from `git log`. Rows
whose fix had not been committed when the table was compiled were marked `uncommitted` and have since been given their hashes (no hash is
invented).

All rows are sorted by commit date, oldest first.
